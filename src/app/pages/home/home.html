Execution Sequence

Component Lifecycle Hooks

Angular manages components from creation to destruction. Tap into key lifecycle moments using lifecycle interface hooks.

Execution Timeline (First render execution order)

01.

constructor()

Class Init

Standard JS class constructor. Ideal for Dependency Injection. Do NOT perform complex logic or API requests here.

02.

ngOnChanges()

Reacts to Inputs

Fires before ngOnInit and whenever data-bound inputs/Signals change. Receives a SimpleChanges map.

03.

ngOnInit()

Component Setup

Fires once after inputs are first initialized. Best place to run HTTP fetch requests or load service state.

04.

ngDoCheck()

Runs during every change detection cycle. Use it to scan for changes that Angular fails to detect automatically.

05.

ngAfterContentInit() & Checked()

Runs after projecting content (<ng-content>) into the component view.

06.

ngAfterViewInit() & Checked()

Runs after component template views and child views are fully loaded. Mandatory for canvas or direct JS DOM plugins.

07.

ngOnDestroy()

Teardown

Runs right before component is removed from DOM. Clean up subscriptions, clear timers, and prevent memory leaks.

Architecture

Understanding Angular Modules (NgModule)

NgModules configure the injector and the compiler. While modern Angular favors Standalone components, modules remain vital for scaling and legacy compatibility.

NgModule Properties (Core Metadata Fields)

declarations: [ ]

Declarations Array

List of components, directives, and pipes that belong specifically to this module. Elements can only belong to exactly one NgModule.

imports: [ ]

Imports Array

List of other NgModules (e.g. CommonModule, RouterModule) whose exported components/directives/pipes are needed by declarations in this module.

exports: [ ]

Exports Array

Subset of declarations that should be visible and usable by any other NgModule importing this module. Allows modular encapsulations.

providers: [ ]

Providers Array

Registers dependency injection providers. Services declared here are available in the module's injector scope (or application-wide scope depending on registration).

bootstrap: [ ]

Bootstrap Array

Only used in the root NgModule (typically AppModule). Defines the main entrypoint component (e.g. AppComponent) to bootstrap first.

Evolution

NgModule vs. Standalone

Angular 14+ introduces **Standalone Components**, removing the strict need for NgModules. Here is how they compare:

Classic NgModule
Modern Standalone
Declared inside an @NgModule
standalone: true in component
Template gets dependencies from container module imports
Dependencies imported directly in component's imports: [...]
Larger initial bundle size due to module boundaries
Better tree-shaking and component-level lazy loading

Architecture

Dependency Injection (DI)

Dependency Injection is a design pattern where a class requests dependencies from external sources rather than creating them itself.

DI Core Concepts

@Injectable()

Injectable Decorator

Marks a TypeScript class as available to be injected. The metadata config option providedIn: 'root' registers it globally, creating a single shared instance (Singleton).

inject() API

Modern Injection Method

The recommended, modern way to resolve dependencies in Angular 14+. It can be used outside constructors (e.g. in initializer fields, custom functions) and enables better type inference.

constructor() injection

Traditional Method

The classic way of requesting services by defining them inside the component's constructor signature, e.g. constructor(private auth: AuthService).

providers: [ ]

Hierarchical Resolution

Angular resolves dependencies hierarchically. Registering a service in a component's providers array creates a new, isolated instance of the service for that component tree.

Comparison

Constructor vs. inject()

Angular supports two styles of injection. The modern `inject()` function is cleaner and works outside classes.

// Classic constructor style
constructor(private auth: AuthService) { }
// Modern inject() style
private auth = inject(AuthService);

Injection Configuration

Angular Providers

Providers instruct the Dependency Injector on how to resolve, construct, or fetch dependency instances for a given token.

Provider Recipes (Resolution Strategies)

useClass

Class Providers

Instantiates a class. Allows replacing a base service class with an extended or alternative class implementation (mocking/customizing behavior).

useValue

Value Providers

Binds a token to a fixed, static value (such as environment configurations, API keys, or application flags). No class instantiation occurs.

useFactory

Factory Providers

Creates a dependency value dynamically by invoking a custom factory function. Can accept inputs and inject other services to determine state.

useExisting

Existing Providers (Aliases)

Maps one injection token to another already existing provider. Acts as a clean alias to prevent duplicate service instantiations.

Scope Hierarchy

Where to Register?

1. Root / Environment Scope

Registered via providedIn: 'root' or in App Config. Shared across the entire app. Tree-shakable.

2. Route Scope

Configured in a specific route's providers array. Loaded and shared only while that route is active.

3. Component Scope

Configured inside component providers: [...] metadata. Creates an isolated instance unique to that component and its children.

Example Code

Configuring Custom Providers

// 1. Value Provider (Static Configuration)
{ provide: API_URL, useValue: 'https://api.com' }
// 2. Class Provider (Implementation swap)
{ provide: LoggerService, useClass: FileLoggerService }
// 3. Factory Provider (Dynamic logic)
{
  provide: SharedConfig,
  useFactory: (auth) => auth.isAdmin() ? adminConfig : guestConfig,
  deps: [AuthService]
}

Language Fundamentals

TypeScript in Angular

Angular is built entirely on TypeScript. Understanding its features like strong typing, decorators, access modifiers, and null safety is essential for clean code.

Key TypeScript Features

Decorators

Metadata & Configuration

Angular uses class decorators like @Component, @Injectable, and @Directive to attach configuration metadata to classes, letting Angular compiler understand how to instantiate and link them.

Type Safety

Interfaces & Strongly-Typed Signals

Compile Time Check

Enforce compile-time safety by declaring interfaces for your data models. This ensures you catch property typos or wrong data assignments immediately. Signals also leverage TypeScript generics (e.g. signal<User[]>([])) to protect your reactive state.

Encapsulation

Access Modifiers & Readonly properties

Use visibility keywords (public, private, protected) and readonly. Protecting your fields guarantees that states are only modified through proper methods, maintaining strict data integrity.

Null Safety

Strict Null Checks & Optional Chaining

Angular projects enable strict null checking by default. This forces developers to explicitly handle potential null/undefined values using optional chaining (?.) or non-null assertion (!), eliminating "Cannot read property of undefined" runtime errors.

Architecture Design

Component Architecture

Components are the primary building blocks of an Angular application. They encapsulate view layouts, styles, and logic under modern standalone conventions.

Key Component Architecture Concepts

@Component

Decorator Metadata

Defines configuration flags like selector, templateUrl or inline template, and styleUrls to control styling.

Standalone

Module-Free Components

Modern Angular components require zero boilerplate NgModules. Enable Standalone mode (default in v19+) to import components, directives, and pipes directly inside the decorator's imports: [...] array.

Data Flow

Inputs & Outputs (Signals)

Send data down to children using inputs (e.g. input() signals) and notify parents of changes using outputs (e.g. output() emitters). This creates a unidirectional and predictable data flow.

Styles & Projection

View Encapsulation & <ng-content>

Scope your CSS styles using ViewEncapsulation.Emulated (default). Project custom template snippets into components using the structural placeholder <ng-content></ng-content>.
