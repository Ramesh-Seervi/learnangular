Execution Sequence

Component Lifecycle Hooks

Angular manages components from creation to destruction. Tap into key lifecycle moments using lifecycle interface hooks.

Execution Timeline (First render execution order)

01.

constructor()

Class Init

Standard JS class constructor. Ideal for Dependency Injection. Do NOT perform complex logic or API requests here.

02.

ngOnChanges()

Reacts to Inputs

Fires before ngOnInit and whenever data-bound inputs/Signals change. Receives a SimpleChanges map.

03.

ngOnInit()

Component Setup

Fires once after inputs are first initialized. Best place to run HTTP fetch requests or load service state.

04.

ngDoCheck()

Runs during every change detection cycle. Use it to scan for changes that Angular fails to detect automatically.

05.

ngAfterContentInit() & Checked()

Runs after projecting content (<ng-content>) into the component view.

06.

ngAfterViewInit() & Checked()

Runs after component template views and child views are fully loaded. Mandatory for canvas or direct JS DOM plugins.

07.

ngOnDestroy()

Teardown

Runs right before component is removed from DOM. Clean up subscriptions, clear timers, and prevent memory leaks.

Architecture

Understanding Angular Modules (NgModule)

NgModules configure the injector and the compiler. While modern Angular favors Standalone components, modules remain vital for scaling and legacy compatibility.

NgModule Properties (Core Metadata Fields)

declarations: [ ]

Declarations Array

List of components, directives, and pipes that belong specifically to this module. Elements can only belong to exactly one NgModule.

imports: [ ]

Imports Array

List of other NgModules (e.g. CommonModule, RouterModule) whose exported components/directives/pipes are needed by declarations in this module.

exports: [ ]

Exports Array

Subset of declarations that should be visible and usable by any other NgModule importing this module. Allows modular encapsulations.

providers: [ ]

Providers Array

Registers dependency injection providers. Services declared here are available in the module's injector scope (or application-wide scope depending on registration).

bootstrap: [ ]

Bootstrap Array

Only used in the root NgModule (typically AppModule). Defines the main entrypoint component (e.g. AppComponent) to bootstrap first.

Evolution

NgModule vs. Standalone

Angular 14+ introduces **Standalone Components**, removing the strict need for NgModules. Here is how they compare:

Classic NgModule
Modern Standalone
Declared inside an @NgModule
standalone: true in component
Template gets dependencies from container module imports
Dependencies imported directly in component's imports: [...]
Larger initial bundle size due to module boundaries
Better tree-shaking and component-level lazy loading
